## Многоагентная организация

### Роли
- Оркестратор (PM): ставит цели и принимает релизы
- Архитектор: проектирует интерфейсы и контракты
- Бэкенд: FastAPI, интеграции с Binance, риск-слой
- Фронтенд: UI, дашборд
- Исследователь стратегий: идеи, бэктесты, параметры
- Риск-менеджер: лимиты, стопы, стресс-тесты
- QA/Тест-инженер: тест-планы, e2e, нагрузочные
- Девопс/Безопасность: CI/CD, секреты, наблюдаемость
- Критик/Ревьюер: ревью PR/RFC и метрик

### Протокол общения
- Каналы: внутренняя шина (NATS), общий knowledge base (docs/ артефакты)
- Артефакты: RFC, PR, отчёты бэктестов, чек-листы релиза
- Правило изменения: риск-ревью + QA-план для любой значимой смены логики

### Жизненный цикл фичи
1. RFC -> согласование
2. Реализация -> автотесты
3. Ревью (Critic + Risk + QA)
4. Сборка/деплой
5. Мониторинг метрик, критерии отката

### План расширений
- Подписки WS (маркет-данные)
- Исполнение ордеров на Testnet (paper mode)
- Сохранение данных в Postgres/Parquet
- Конструктор стратегий и бэктестов в UI
- Наблюдаемость (Prometheus/Grafana) и алерты

### Полномочия на изменения кода и перезапуски
- **Кто меняет код**: агенты ролей `backend`, `frontend`, `strategy_researcher` создают предложения изменений через API `agents` (`POST /agents/propose_code_change`). Изменения применяются через Git (ветка/PR) и CI/CD после ревью `risk_manager` + `qa_engineer` + `critic`.
- **Кто перезапускает сервисы**: агент `devops` использует `POST /agents/restart_service` для инициации безопасного рестарта (на практике дергает CI/CD job или orchestrator, а не напрямую в проде).
- **Оркестратор** принимает финальные решения по мерджу и релизу.

### Где "мозг" агентов
- Контрольная плоскость — сервис `agents` (FastAPI). В нем описаны роли, эндпоинты планирования и предложений изменений.
- Подключение к LLM (например, GPT‑5) через переменную `OPENAI_API_KEY`. Статус подключения виден на `GET /health` сервиса `agents` (поле `llm_connected`).
- Вызовы LLM используются для генерации планов, ревью и обсуждений. Реализация полноценных диалогов и автогенерации PR предлагается внедрять постепенно.

### Подключение к GPT‑5 (через аккаунт создателя)
- Установлено в коде `services/agents` (см. `requirements.txt` и инициализацию клиента в `app/main.py`).
- Настройка: задайте `OPENAI_API_KEY` в `.env`.
- Без ключа сервис работает в деградированном режиме (LLM недоступен, но API отвечает и показывает `llm_connected: false`).
